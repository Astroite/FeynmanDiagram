## 1. 执行结论

当前仓库已经形成一个可信的早期玩法工程原型，但还不是垂直切片。最扎实的部分是“图模型优先”的基础架构、可撤销交互命令、程序化曲线渲染，以及在当前阶段相当健康的自动化测试基础。工程能够稳定启动，锁定的 Godot 引擎存在且版本正确，现有 84 个测试全部通过。

项目目前尚不具备通过 Gate A（手感原型验收）的条件，主要原因是若干正确性缺陷会让玩家绕过谜题目标，同时六个教程关卡还没有经过正式的陌生玩家测试。项目也不能被视为已经完成 QED 玩法原型：目前只有一个 QED 关卡和一个局部顶点检查器，设计要求的完整验证管线、外部态检查、观测脉冲、四级提示、关卡约束、题型多样性和内部编辑器仍未实现。

相对于当前短期目标，进度估算如下：

| 指标 | 估算 | 依据 |
|---|---:|---|
| P0 实现覆盖率 | 65–75% | 大多数规划动词和六个教程资源已存在，但完成判定、操作分阶段开放、脉冲行为、触控完整性和人工验收仍未解决。 |
| P0 验收进度 | 0% | 没有记录陌生玩家测试、低配置性能验证或正式 Gate A 决策。 |
| P1 实现覆盖率 | 15–25% | 已有粒子目录、一个硬编码 QED 语法、托盘/拉线动词和一个 QED 关卡；大部分 P1 系统和内容尚不存在。 |
| P2 实现覆盖率 | 5–10% | 已有星系地图外壳和初步视觉方向；拓扑图族、进度、存档、设置、无障碍、最终美术音频和公开试玩包装均未完成。 |

## 5. 优先级问题

### P0-1：删除关卡原始内容可以直接通关

**严重级别：阻断**  
**证据：** `GraphModel.is_complete()` 只检查悬空半边和图连通性（`game/core/graph/GraphModel.gd:164`）；`is_graph_connected()` 对零个或一个节点直接返回真（`game/core/graph/GraphModel.gd:177`）。谜题 HUD 允许删除任何选中的原始节点或边。临时运行探针删除第 001 关已连接的 `left` 锚点后，其关联边被删除，只剩一个节点，关卡随即被判定完成。

**影响：** 玩家能够绕过设计交互。相同机制允许继续删成空图，而空图本身也会报告完成。

**必要修复：** 完成判定必须感知关卡目标。应先验证必需原始端点/节点、不可变 givens、最小结构、允许动作、外部态和关卡特定目标，再进行图完整性判定。不允许删除的关卡不得暴露删除操作。

### P0-2：撤销历史跨关卡和重开残留

**严重级别：阻断**  
**证据：** `CurveInteraction.set_graph_model()` 更换图并清除选择，但没有清空或重新绑定撤销栈（`game/interaction/CurveInteraction.gd:112`）。探针在第 001 关执行一次操作、加载第 002 关后，仍得到 `can_undo == true` 且撤销计数为 1。

**影响：** 步数错误，重开不是真正重置，撤销可能执行仍引用旧图的命令。这同时属于正确性和对象生命周期风险。

**必要修复：** 每次安装模型或重开关卡时，取消当前手势并清空撤销/重做栈。增加加载、重开、胜利、重玩和下一关之间的生命周期测试。

### P0-3：图重新变为非法后，“已完成”状态仍被锁死为真

**严重级别：阻断**  
**证据：** `LevelRuntime.evaluate_completeness()` 在首次通过时设置 `_is_complete`，之后从不重置，并直接返回锁存值（`game/level/LevelRuntime.gd:61-71`）。探针载入参考解、删除其边后，出现 `is_level_complete == true` 但 `validation_status.ok == false`。

**影响：** 运行时、HUD 和未来进度系统可能互相矛盾；重玩、延迟结算、统计或存档可能记录错误通关。

**必要修复：** 将“当前是否合法”与“是否已经发出过完成事件”分开。每次图变化都重新计算当前合法性，完成信号只在假到真的边沿触发。

### P0-4：QED 验证器接受没有相互作用顶点的图

**严重级别：P1 阻断**  
**证据：** `PhysicsGrammar.validate()` 跳过所有非顶点节点；若图完整但没有任何相互作用顶点，循环结束后直接成功（`game/core/physics/PhysicsGrammar.gd:30`）。探针用一条光子边连接两个外部锚点，QED 验证返回 `ok == true`。

**影响：** 一个完全没有 QED 相互作用的连通图也能被称为物理合法；外部粒子要求和关卡指定过程没有得到执行。

**必要修复：** 实现文档规定的完整管线：必需端点、图完整性、顶点模板、费米子流与外部态、精确整数守恒、允许拓扑和关卡目标。验证函数必须同时接收图和当前 `LevelSpec`。

### P0-5：每一关都开放全部粒子和拓扑编辑动词

**严重级别：高**  
**证据：** `LevelSpec` 没有允许动作或允许粒子字段（`game/level/LevelSpec.gd:4-14`）。`PuzzleHud` 始终创建五个 QED 粒子按钮和一个新端点按钮（`game/ui/screens/PuzzleHud.gd:135-150`），同时按条件开放提示、删除、切割、反转、重开和世界操作。

**影响：** 第一关就违背“每关最多引入两个新操作”的设计规则。玩家会看到未解释的粒子，还可以在目标之外修改拓扑；这也是多数通关漏洞的入口。

**必要修复：** 在 `LevelSpec` 中加入数据驱动的动作和粒子权限；对每个教程关卡做最小配置；权限必须在运行时/交互层执行，而不只是隐藏 UI。

### P0-6：费米子流、几何顺序和时间方向没有在行为上独立

**严重级别：高架构债务**  
**证据：** `GraphEdge.time_axis_dir` 和 `HalfEdge.fermion_flow` 会被序列化，但 `PhysicsGrammar` 不读取它们。箭头方向由粒子正负号以及半边位于 `a` 端还是 `b` 端推导（`game/core/physics/PhysicsGrammar.gd:90`）。反转操作同时交换半边并反转曲线点顺序（`game/core/graph/GraphModel.gd:121`）。

**影响：** 这违背核心架构不变量。后续实现外部态、交叉过程和反粒子规则时，可能不得不修改存档数据和交互语义。

**必要修复：** 为几何遍历、时间轴方向和费米子流引入独立枚举/字段。渲染、验证和反转操作应分别读取对应语义。

### P0-7：曲线交互命中的形状与实际渲染形状不同

**严重级别：高手感风险**  
**证据：** 渲染器使用 `Curve2D` 烘焙点绘制；边选择和最近线段逻辑却只测量控制点之间的直线段（`game/interaction/CurveInteraction.gd:554-570`、`906-914`）。切割逻辑虽然会修正端点位置，但仍使用控制点折线而不是实际 Bézier/波形。

**影响：** 玩家可能点不到视觉上明显弯曲的线，却能点中不可见的弦线。这直接威胁 Gate A 中“误操作不应成为主要负面反馈”的指标。

**必要修复：** 渲染器与交互层共享缓存的烘焙曲线几何；用宽容半径命中可见核心曲线，并增加强弯曲回归测试。

## 6. 代码与架构审查

### 优点

- 当前完成判定以图而非像素为事实来源。
- 连接由占用插槽的两个半边组成，基础抽象正确。
- 曲线几何没有参与物理验证。
- 电荷和轻子数已经有整数单位字段，没有对守恒量使用浮点容差。
- `GraphModel` 发出聚焦的变更信号，并能确定性序列化图快照。
- 命令系统使主要状态操作可逆，并对混合操作序列进行了测试。
- 关卡使用资源数据而不是定制脚本，每个现有关卡都有参考快照。
- 一方代码总体可读，注释充分。
- LFS 正确管理引擎和二进制美术，`.godot/` 生成数据没有入库。

### 可维护性风险

- `CurveInteraction.gd` 约 971 行，`CurveRenderer.gd` 约 801 行，各自包含多个独立职责，并重复了端点/控制柄几何逻辑。
- 粒子颜色和样式分别硬编码在渲染器与谜题 HUD 中，未来容易漂移。
- 信号载荷和验证结果大量使用弱类型字典，协议变化容易漏改。
- `LevelSpec.to_dict()` 没有包含 `ruleset`；未来关卡工具若使用该序列化方法，可能把 QED 关卡静默转成拓扑关卡。
- `GraphModel.from_dict()` 信任关卡字典，不返回结构化的制作错误；重复或损坏数据可能在较晚阶段才失败。
- 多步骤命令的撤销方法没有统一传播部分恢复失败，异常时可能让撤销栈和图状态不一致。
- 拓扑变化经常触发整个渲染器重建。对七个小图尚可，但在更大的图族关卡前必须测量。
- 没有内容模式版本或存档版本。

| 循环步骤 | 状态 |
|---|---|
| 观察固定端点和半成品图 | 已实现。 |
| 拖节点、弯曲线、连接半边、反转箭头 | 已有较完整的原型。 |
| 通过光晕、声音、局部脉冲感知接近合法 | 只有部分视觉反馈；没有声音和物理感知脉冲。 |
| 主动触发观测脉冲 | 缺失。HUD 目前只有直接载入参考解的提示。 |
| 定位并修正第一个局部错误 | 只有单行验证文字，没有图遍历或局部错误演出。 |
| 合法后自动共振 | 有即时完成信号和装饰性逐边脉冲。 |
| 可选科学透镜 | 缺失。 |

当前实现正确地避免了几何通关条件，这是重要的设计成功。不过现有循环更接近“不断编辑，直到状态文字变为合法”，还不是“观测脉冲—定位物理错误—理解—共振”。

### 教程序列

- 第 001、002、004、005 关在机制上非常接近：把一个自由端点拖到唯一可用插槽。
- 第 002 关名义上教授弯曲，但几何不能也不应决定通关；现有机制没有确保玩家真正学会曲线弯折。
- 第 004 关无法实现其“撤销重做”教学目标。第一次连接成功会立即发出完成事件并切换胜利界面，玩家来不及练习撤销与重做。
- 从第 001 关起就显示全部粒子托盘和新增端点，而粒子身份尚未教学。
- 删除、切割、新增端点、粒子种子、完整参考解等操作没有关卡权限限制。
- 提示按钮直接安装完整参考图，因此会直接完成关卡。这只能作为临时调试逃生口，不能作为正式提示体验。

### QED 深度

第 007 关是一个有价值的视觉与数据集成冒烟测试。它包含完整湮灭图，只留下正电子腿未连接。所需操作十分明显：把唯一的自由端接到唯一开放的顶点插槽。这尚不能证明 QED 规则能产生推理，而非盲目放置。

该关的章节分类也不一致：星图把它放在第一幕，但玩家显示代码仍为“序章 · 07”。权威设计把序章定义为 1–6 关，第一章定义为 7–14 关。

### Gate 判定

**Gate A：尚不能进入验收。** 在试玩之前，需要修复结果可信度、限制关卡动作、确保每个教程目标能被机制证明，并让命中检测与渲染曲线一致。随后按设计指标执行并记录陌生玩家测试。

**Gate B：尚未具备条件。** 一个补全谜题和一个硬编码顶点语法不能证明三种可重复 QED 题型，更不能证明四类题型成立。路线图不应推进到 P1 验收。

## 9. 视觉、美术与 UI 审计

### 已经有效的部分

- 深蓝/紫色调与“安静的量子仪器”方向一致。
- 画布仍是视觉主体，界面边缘控件数量有限。
- 费米子与光子在基础层面容易区分，光子波形尤其清晰。
- 费米子箭头、发光、选择环、控制柄、吸附提示和切割轨迹能够表达交互状态。
- 星系式关卡地图比普通列表更符合产品方向，并已经支持平移和缩放。
- 视觉主要由程序生成，原型阶段对资产依赖低。

### 相对于参考图和目标的主要差距

- 主菜单只有一个大型“开始游戏”按钮，没有产品标题、Logo、副标题或视觉焦点，首次启动几乎没有产品识别。
- 运行时没有使用现有风格图或等效正式资产。背景主要是重复的同心径向色带、星点和四条流线，更像程序化占位图，而不是深邃精密的量子仪器。
- QED 画布没有外部粒子符号，玩家只能通过颜色和箭头推断身份。
- 电子与缪子使用相同实线语法，主要依赖颜色区分，不满足无色彩识别要求。
- 实光子与虚光子没有独立数据或视觉状态。
- 相互作用顶点只是简单实心圆，缺少参考图中的插槽、相位、合法性和局部错误状态。
- 星图没有锁定/可用/完成状态、进度路径或真实进度数据，所有关卡都能直接选择。
- `LevelSelectScreen` 手动把世界坐标转换为屏幕坐标，却又对标签应用反向缩放（`game/ui/screens/LevelSelectScreen.gd:213-214`），导致放大时文字变小、缩小时文字变大，而不是保持恒定可读。
- 多数 UI 使用 1280×720 设计空间中的绝对坐标。工程请求 2560×1440 窗口并使用 `canvas_items + expand`，尚未证明 16:10、Steam Deck、小窗口和安全区适配。
- 完成演出对所有边使用相同持续时间（`game/render/CurveRenderer.gd:415`），因此不同长度边的脉冲速度不同，不符合近似匀速原则。
- 没有减少动态模式；星空、背景流线、星图节点、转场和脉冲都会持续动画。

### 美术生产风险

- 除测试插件自带资源外，没有集成游戏字体、贴图、VFX 贴图或正式 UI 资产。
- 没有记录资产命名/导入规范、源文件到运行时的管线或美术预算。
- 参考图的来源和可用于正式产品的授权状态没有文档记录。在权属/许可明确前，应只把它们当参考图使用。
- 没有截图对比或视觉回归基线。

当前画面适合作为灰盒/手感原型，但还不足以代表 P2、公开试玩或商店曝光质量。

## 10. 音频、无障碍与平台审计

### 音频

工程中没有游戏音频文件、音频总线、播放系统、自适应层、粒子声音身份、交互音效或完成短句。声音目前无法参与手感与验证。游戏确实可以静音运行，但这是因为音频缺失，而不是已经完成多模态无障碍设计。

### 无障碍

- 光子与费米子有形状区别；电子与缪子没有。
- 玩法画布缺少外部态标签和符号。
- 没有减少动态、减少闪烁、字体缩放、高对比度、色盲方案、按键重映射、旁白或字幕设置。
- 原生按钮可获得焦点，是良好基础；自定义星图节点没有键盘/手柄焦点语义。

### 输入与布局

- 已有鼠标操作和键盘撤销/重做/删除/取消。
- 世界手势有直接触摸事件路由。
- 托盘拖动代码明确处理鼠标事件，完整触控行为尚未证明。
- 没有手柄导航。
- 默认请求窗口为 2560×1440，对很多桌面和掌机显示器并不是合适的未经验证默认值。
- 设计列为第一优先级的 16:10 与小屏行为仍未验证。

## 11. 内容、工具和发行准备度审计

### 内容数据

关卡使用 `.tres` 数据并带有参考解，是正确方向。但当前 `LevelSpec` 过于简单，至少还需要：

- 必需/固定外部端点及其外部粒子状态；
- 允许动作和允许粒子；
- 接受的拓扑规则和要求解数量；
- 提示链和完成演出；
- 章节/进度元数据；
- 模式版本和验证诊断。

关卡目录是硬编码路径数组，星系归属又是另一份硬编码索引数组。新增或重排关卡时可能静默分类错误。

### 内部工具

没有 `ContentTools` 实现。当前不存在非程序员关卡编辑器、拓扑哈希、动作/粒子配置界面、保存时自动验证、多分辨率预览或批量内容报告。这是后续生产的核心瓶颈，而非装饰性缺项。

### 发行工程

- 没有 `.github/` CI 工作流。
- 没有导出预设或导出验证任务。
- 没有项目级许可证文件。
- 根目录 `README.md` 只有仓库名称。
- 没有崩溃报告、结构化日志、试玩统计或版本化存档格式。
- 没有本地化源文件，玩家文字直接写在脚本和资源中。

Git LFS 和生成文件管理良好。当前最需要的是导入、无头启动和测试 CI，而不是完整发行流水线。

## 12. 项目管理与文档健康度

多份工作文档已经不能准确描述仓库：

- `AGENTS.md` 仍称实现尚未开始、Godot 工程不存在，但仓库已经有数千行运行时代码和 84 个测试。
- `agents/tasks/README.md` 称迭代 0 即将进入实现，但大部分 P0 代码以及若干 P1 实验已经存在。
- `agents/tasks/handoff-completion-roadmap.md` 称托盘、粒子数据和 QED 验证不存在，但这些现在都已有部分实现。
- 最后一份旧工作日志早于多个 6 月 23 日交互提交和 7 月 3 日 UI 提交。
- 根目录 `plan.md` 描述星系地图重写，却没有标明已完成、已验收或被替代。
- 至少一个近期提交标题使用中文，违背仓库制品使用英文的约定。

文档漂移会使完成度估计失真，也会增加在早期 Gate 未通过前提前实现后期系统的概率。应在正确性修复后更新路线图，并明确记录 Gate A 证据。

## 13. 建议修复路线

### 阶段 0：恢复结果可信度

1. 定义感知关卡目标的验证输入和结构化 `ValidationResult`。
2. 向 `LevelSpec` 加入必需端点/givens、允许动作、允许粒子和最小图约束。
3. 拒绝空图/平凡图，并执行外部态与关卡目标。
4. 每次安装模型时清空撤销/重做并取消手势。
5. 将当前合法性与一次性完成事件分离。
6. 为每个已复现问题增加对抗性回归测试。
7. 在 UI 和运行时两层按关卡限制删除、切割、新增、种子、反转和提示。

**退出条件：** 任何关卡都不能通过删除必需内容、修改禁止内容、执行旧关命令或生成目标范围之外的图而通关。

### 阶段 1：真正完成 P0 教程与 Gate A

1. 重做六个教程关卡，使每关都有不同且可被机制观察的学习目标。
2. 重构第 004 关，让撤销/重做发生在通关之前，或取消其关卡目标身份。
3. 在关卡数据开放前隐藏 QED 托盘和高级动词。
4. 使用烘焙 Bézier 几何做命中，并用强弯曲场景调整吸附/命中半径。
5. 提供真正近似匀速的脉冲和完成演出跳过路径。
6. 在真实设备上测试鼠标和触摸，并覆盖 16:9、16:10 与小屏。
7. 按设计指标执行并记录陌生玩家 Gate A 测试。

**退出条件：** 前三关无需开发者解释即可理解，预定操作无法被绕过，拖节点与弯曲线能够明确区分，撤销覆盖所有状态变化，并且手感通过真人评审。

### 阶段 2：在稳定语义上构建 P1

1. 在模型和测试中分离几何方向、时间轴方向和费米子流。
2. 实现数据驱动的 `VertexRule`，并完成外部态和精确守恒阶段。
3. 实现物理感知的 `PulseSimulation` 与四级 `HintDirector`。
4. 制作三种真正不同的 QED 题型，并验证它们能产生推理。
5. 在关卡数量扩大前完成 `ContentTools`。
6. 增加关卡模式验证和 CI 批量检查。

**退出条件：** 至少三种 P1 题型通过陌生玩家测试，编辑器能够在不改代码的情况下制作和验证内容。

### 阶段 3：之后再向 P2 扩展

进度/存档、拓扑图族、最终美术音频、设置、无障碍、公开试玩包装和商店素材都应保持在 Gate A 与 Gate B 之后。当前星图可以作为外壳保留，但在真实进度数据接入前不应继续投入大量打磨。

## 15. 最终建议

项目值得继续，但当前版本应被视为工程原型。现有基础足以支持一次聚焦的稳定化迭代。当前最高价值工作不是增加更多界面或进一步打磨视觉，而是让关卡结果可信、缩小教程操作范围、使交互命中与可见曲线一致，并取得第一批真实 Gate A 试玩证据。完成这些工作后，现有图模型、命令和渲染基础可以支撑更干净的 P1 实现，而不继续放大语义债务。
